# dev set 구축

상태: 완료. 영어 정본 `data/gold/dev_set.jsonl` 38문항, 한국어 번역 묶음 `data/gold/dev_set_ko.jsonl` 38문항. 행 스키마는 `data/gold/README.md`.

## 목적

선정 실험(데이터베이스, Embedding, 토크나이저, Chunking, 거절 임계값, LLM)에서 후보를 비교하는 질의셋. 최종 평가용 test set과 분리해, 같은 셋으로 고르고 평가해서 점수가 부풀려지는 것을 막는다.

## 구성

| 유형 | 문항 | 근거 구절 | 원문 표집 규칙 |
|---|---|---|---|
| factual | 12 | 문항당 1개 | 최상위 섹션을 번갈아 뽑음 |
| multi_doc | 8 | 문항당 2~3개 | 실제로 서로 링크된 문서 쌍. 쌍끼리 문서가 겹치지 않음 |
| summary | 5 | 문항당 4~5개 | 6,000자 이상 문서 |
| trap | 5 | 문항당 1~2개 | preview, experimental, deprecated, 버전 번호 표기가 3개 이상인 문서 |
| unanswerable | 8 | 없음 | 문서 전체의 H1, H2 목차만 주고 생성. 근접 주제 4, 먼 주제 4 |
| 합계 | 38 | 62 | |

- 원문 범위: 근거가 걸린 문서 38개(Corpus 81개 중, 1,500자 이상 문서 59개 중). 섹션별로 concepts 16, guides 11, pip 4, reference 4, getting-started 3.
- 1,500자 미만 문서(목차, 안내 페이지)는 표집에서 뺐다.
- 질문 길이 중앙값은 영어 106자, 한국어 68자. 근거 구절 길이 중앙값은 153자.
- 선정 실험이 검색과 형식 준수만 보므로 수용 기준(`acceptance_criteria`)은 쓰지 않았다. test set에서 채운다.

## 방법

### 1. 영어 초안 생성

- 명령: `make gold-draft SPLIT=dev`
- 모델: `gpt-6.1-terra`(엘리스 ML API), JSON Schema 구조화 출력. 원문 표집 seed 2026, 생성 seed 42.
- 입력: 유형별 지시, 공통 규칙(자연스러운 사용자 질문, 문서를 언급하지 않음, 근거는 원문 그대로 복사), 원문 전체를 `<document>` 태그로 감쌈. 태그 안의 지시는 따르지 말라고 시스템 프롬프트에 명시했다.
- 근거 검증: LLM이 낸 인용을 원문과 대조했다. 공백 차이만 허용하고 나머지는 글자 단위로 비교한다(`app/service/eval/evidence_matcher.py`). 실패하면 실패한 인용을 알려주고 1회 재시도, 다시 실패하면 그 문항을 버린다. multi_doc은 두 문서 모두에서 인용이 나와야 통과한다.
- 결과: 38문항 생성, 버린 문항 0개. LLM 호출 31회.

### 2. 검수

38문항을 모두 읽고, 답 없는 문항은 핵심어(Conda, Nexus, 1Password, autoscaler, timeout, concurrent 등)를 원문에서 검색해 실제로 답이 없음을 확인했다.

| 문항(교체 전 이름) | 조치 | 이유 |
|---|---|---|
| `dev-factual-01` | 교체 | 원래 질문(uv의 구현 언어)은 모델이 문서 없이도 아는 내용이라 검색 비교에 변별력이 없음. 자격 증명 저장 위치 질문으로 교체 |
| `dev-trap-05` | 교체 | 원래 질문(상세 로그 플래그 `-v`)은 일반 지식으로 맞힐 수 있어 함정이 아님. CycloneDX SBOM 내보내기(preview 기능) 질문으로 교체 |
| `dev-unanswerable-04` | 교체 | 원래 질문(사용자 회사의 파이프라인 지표)은 문서와 동떨어져 쉽게 거절됨. 근접 주제 문항(HTTP 요청 시간 제한)으로 교체. 문서에는 캐시 잠금 대기 시간(`UV_LOCK_TIMEOUT`)만 있어 검색이 이 구절을 가져와 오답을 유도할 수 있음 |
| `dev-unanswerable-05` | 교체 | 원래 질문(1Password 보관 기간)도 같은 이유. 근접 주제 문항(다운로드 동시성 기본값)으로 교체. 문서에는 여러 명령의 동시 실행(캐시 잠금) 설명만 있음 |
| `dev-unanswerable-01` | 메모 추가 | 문서는 활성화된 Conda 환경 감지만 언급. "이미 지원한다"는 오답을 유도하는 근접 문항으로 유지하되 부분 답변 여지가 있음 |
| `dev-multi_doc-05` | 질문 수정 | 프로젝트 흐름(`uv init`, `uv add`)이 아니라 pip 호환 인터페이스를 묻는다고 명시 |

교체 문항은 원문을 읽고 작성했고 근거 인용을 원문과 대조했다. 이후 사람 검토를 거쳐 정본 76행의 `origin`을 `llm_draft_reviewed`로 바꿨다.

### 3. id 부여

문항 id는 UUID다. 무작위 `uuid4`는 쓰지 않고 `uuid5(GOLD_ID_NAMESPACE, "<split>-<type>-<순번>")`으로 계산한다. 초안을 다시 만들거나 질문 문장을 고쳐도 id가 바뀌지 않아, 이후 실험 결과와 사람 라벨이 문항을 계속 참조할 수 있다. 위 표의 교체 전 이름에 이 규칙을 적용하면 현재 id가 나온다.

### 4. 한국어 번역 묶음

- 명령: `make gold-translate SPLIT=dev`. 모델 `gpt-6.1-terra`, 8문항씩 5회 호출(게이트웨이의 비스트리밍 출력 상한 2,000토큰 안에 들어가도록 묶음).
- 질문만 옮겼다. 명령, 플래그, 환경변수, 설정 키, 파일 경로, 제품명, 백틱 안 내용은 번역하지 않도록 지시했다. 정답과 근거는 원문 행 그대로이고, `translation_of`로 원문 행을 가리킨다.
- 검수: 38문항을 원문과 나란히 읽었다. 의미 누락, 추가, 식별자 번역은 없었다. 같은 용어(credentials)가 문항에 따라 "인증 정보", "자격 증명"으로 옮겨진 차이만 있어 그대로 두었다.
- 쓰임: 한국어 질의가 영어 Corpus에서 얼마나 손해를 보는지 문항 단위로 비교한다. "질의를 번역하면 한국어 질의의 Hit@k가 오른다"는 Part C 가설 후보의 근거가 된다.

### 5. 검증

`make gold-check SPLIT=dev LANG_CODE=en|ko`가 스키마, id 중복, 근거 인용의 원문 일치, 번역 행과 원문 행의 짝(유형, 근거, 정답 일치와 누락 여부)을 검사한다. 영어, 한국어 모두 문제 0건.

## 한계

- 초안과 교체 문항을 모두 LLM(gpt-6.1-terra, Claude)이 작성했다. 사람 검토는 했지만 작성자가 한 명이라 질문 문체가 단조로울 수 있다.
- LLM 초안은 근거가 한 구절 안에 들어가는 질문으로 쏠리는 경향이 있다. factual 12문항이 모두 근거 1개다.
- 초안 생성 모델이 LLM 선정 후보이기도 하다. 그 모델에 유리한 문체로 질문이 쏠렸을 수 있다.
- `dev-multi_doc-01`은 질문 하나에 세 가지를 묻는 인위적인 문장이다. 검색 실험에는 문제가 없어 유지했다.
- 답 없는 문항 8개 중 4개(인력, Nexus 관리, GitHub 브랜치 보호, Kubernetes HPA)는 문서와 먼 주제라 쉽게 거절될 수 있다. 거절 임계값 보정에서는 근접 주제 4문항의 비중을 따로 본다.
- 한국어 묶음의 정답은 영어다. 한국어 답변을 평가할 때 언어가 다른 정답과 비교하게 된다.
- Corpus에는 uv의 CLI 레퍼런스와 환경변수 레퍼런스 페이지가 없다(문서 빌드 때 생성되는 페이지라 저장소에 없음). 식별자 질문은 개념 문서 본문에 나오는 식별자로만 만들었다.

## 재현

```
make corpus                          # 원문
make gold-draft SPLIT=dev            # 영어 초안 → data/gold/drafts/dev_draft.jsonl
make gold-translate SPLIT=dev        # 한국어 초안 → data/gold/drafts/dev_ko_draft.jsonl
make gold-check SPLIT=dev LANG_CODE=en
make gold-check SPLIT=dev LANG_CODE=ko
```

원문 표집은 seed로 고정되지만 LLM 출력은 매번 달라질 수 있다(이 모델은 temperature를 고정할 수 없음). 그래서 재실행은 `drafts/`만 덮어쓰고, 정본은 이번 검수 결과를 그대로 유지한다.
