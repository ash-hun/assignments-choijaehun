# 데이터셋 선정

상태: 확정(`uv_docs`). 사전 등록한 closed-book 판정 기준은 만족하지 못했고, 판정 지표를 바꿔 확정했다. 경위는 "사전 기준과의 차이" 절에 있다.

## 질문

어떤 Corpus가 과제 제약(문서 20개 이상 또는 50페이지 이상, 재현 가능, 공개 가능)을 만족하면서 Hallucination과 검색 난이도를 가장 잘 드러내는가.

## 후보

| 이름 | 원천 | 고정 commit | 언어 | 라이선스 | 선정 이유 |
|---|---|---|---|---|---|
| `uv_docs` | `astral-sh/uv` `docs/` | `5ce34500b8a3` | 영어 | Apache-2.0 또는 MIT | 출시 2년 남짓, 릴리스가 잦아 모델 사전 지식이 낡았을 가능성 |
| `k8s_ko_concepts` | `kubernetes/website` `content/ko/docs/concepts/` | `3ce2ad7b7a23` | 한국어 | CC-BY-4.0 | 구조가 깊고 버전별 기능 상태 표기가 많음 |
| `es_toolkit_ko` | `toss/es-toolkit` `docs/ko/` | `c70e15eab45a` | 한국어 | MIT | 2024년 공개, 모델 사전 지식이 적을 가능성 |
| `fastapi_ko` | `fastapi/fastapi` `docs/ko/docs/` | `1ca09c13584c` | 한국어 | MIT | 모델이 잘 아는 주제. closed-book 대조군 |

원천 정의는 `data/corpus/candidates.json`, 파일별 sha256은 `data/corpus/manifests/<이름>.json`. 원문은 저장소에 넣지 않고 manifest로 재현한다.

후보에서 뺀 것: `langchain-ai/langgraph`(문서 디렉토리가 저장소에서 빠져 고정 commit으로 받을 수 없음), 정부 정책 FAQ(사이트 개편 시 같은 원문을 다시 받을 방법이 없어 재현성 기준 탈락 예상, 미검증).

## 방법

1. `make corpus`: 후보별 원문을 고정 commit에서 받고 sha256 기록. 두 번째 실행은 0.4초, 새로 받은 파일 0개로 재실행 안전성 확인.
2. `make profile`: 후보별 규모, 구조, 파싱 난이도, 함정 요소 지표 측정. 결과 `research/artifacts/dataset_profile.json`.
3. closed-book 검증: 후보마다 원문에서 10문항(버전 관련 4, 세부 사실 3, 개념 3)을 뽑고, 같은 모델, 같은 프롬프트, seed 42/43/44로 문서 없이 질의(모델이 temperature 고정을 지원하지 않아 반복으로 대신함). 문항은 `data/selection/closed_book/<이름>.jsonl`, 40문항 전부 근거 인용이 원문과 글자 단위로 일치함을 확인.

환산 페이지는 관례값(한국어 1,500자, 영어 3,000자가 한 쪽)으로 계산했다. 마크업 잡음은 Hugo shortcode, HTML/JSX 태그, admonition 표기 수다. 내부 링크는 외부 URL, 메일, 같은 문서 안 앵커를 뺀 링크로, 문서끼리 서로 참조하는 정도(다중 문서 종합 문항을 만들 재료)를 가늠한다.

해석:

- **규모**: 네 후보 모두 과제 하한(50페이지)을 3배 이상 넘는다. 규모로 탈락하는 후보는 없다.
- **파싱 난이도**: `k8s_ko_concepts`의 마크업 잡음이 문서당 15.4로 다른 후보의 4배 이상이다. Hugo shortcode를 정제하는 코드가 추가로 필요하다.
- **문서 성격**: `es_toolkit_ko`는 코드 비율 52%, 중앙값 1,228자로 같은 틀의 API 레퍼런스 페이지가 대부분이다. compat 버전과 main 버전에 이름이 같은 함수 페이지가 따로 있어 검색 혼동을 유발하는 함정은 풍부하다. 반면 버전 표기가 거의 없고, 여러 문서를 종합해야 하는 질문은 compat과 main 비교 정도로 제한될 가능성이 있다(추정).
- **다중 문서 연결**: `k8s_ko_concepts`(문서당 10.55, 92%)와 `uv_docs`(4.88, 88%)는 대부분의 문서가 다른 문서를 참조한다. `es_toolkit_ko`는 61%의 문서가 다른 문서를 전혀 참조하지 않는다. 함수별 레퍼런스 페이지가 각자 독립적이라 여러 문서를 종합하는 문항을 만들기 어렵다.
- **함정 요소**: `uv_docs`가 문서당 버전 표기 3.58로 가장 많다. 실험적 기능, 미리보기 기능, 버전별 동작 차이가 질문 재료가 된다.
- **번역 지연**: `k8s_ko_concepts`, `fastapi_ko`는 번역본이라 영어 원본보다 늦을 수 있다. Gold Set 정답을 번역본 기준으로 고정하면 문제는 없지만, 모델의 사전 지식(영어 최신판)과 번역본이 다른 경우 오답 판정이 모호해진다.

## 결과: closed-book

모델 `gpt-6.1-terra`(엘리스 ML API), 후보당 10문항 × seed 3개(42, 43, 44) = 120회 질의. 이 모델은 temperature를 기본값(1) 외에는 받지 않아 seed를 바꿔 반복했다. 채점은 후보 이름을 가리고 순서를 섞은 뒤 가설을 모르는 별도 채점자(Claude Opus)가 루브릭으로 했다. 문항 판정은 3회 답변의 다수결(과반 없으면 부분 정답)이다.

| 지표 | uv_docs | k8s_ko_concepts | es_toolkit_ko | fastapi_ko |
|---|---|---|---|---|
| 답변 120건 중 정답 | 18/30 | 30/30 | 19/30 | 30/30 |
| 답변 중 오답 | 4/30 | 0/30 | 3/30 | 0/30 |
| 답변 중 모름 | 8/30 | 0/30 | 8/30 | 0/30 |
| **문항 판정 오답** | **1/10** | 0/10 | 1/10 | 0/10 |
| 문항 판정 모름 | 3/10 | 0/10 | 3/10 | 0/10 |
| 지식 공백(오답 + 모름) | 4/10 | 0/10 | 4/10 | 0/10 |
| 3회 판정이 모두 같은 문항 | 9/10 | 10/10 | 8/10 | 10/10 |

원자료: `research/artifacts/closed_book/`(답변, 채점 키, 채점 결과, 요약). 재현: `make closed-book`, `make closed-book-report`. 오답 판정 7건은 참조 답, 근거 인용과 다시 대조해 판정이 맞음을 확인했다.

관찰:

- **사전 등록 기준(오답 문항이 대조군보다 3개 이상 많음)을 만족한 후보는 없다.** 가장 많은 uv_docs, es_toolkit_ko도 대조군보다 1개 많다.
- **k8s_ko_concepts는 대조군과 똑같이 30회 전부 정답이다.** 모델이 근거 없이도 다 아는 Corpus라 RAG의 필요와 Hallucination을 보이기 어렵다.
- **uv_docs와 es_toolkit_ko는 지식 공백이 똑같이 4/10이다.** 두 후보를 합친 8/20과 대조군 쪽 0/20의 차이는 Fisher 정확 검정 양측 p ≈ 0.003으로 우연으로 보기 어렵다. 후보 하나씩(4/10 대 0/10)은 p ≈ 0.09다.
- **실제 Hallucination 사례가 나왔다.** `uv_docs-10`(pre-release 기본 처리)은 3회 모두 예전 버전 uv의 동작을 현재 동작처럼 답했다. 낡은 사전 지식이 Hallucination으로 이어지는 전형이다. `es_toolkit_ko-05`는 `retries` 기본값을 Infinity가 아닌 3으로 지어냈다(3회 중 2회).

측정 도구의 한계: 질의 프롬프트에 "확실하지 않으면 모른다고 답하라"를 넣었다. 그래서 지식 공백 대부분이 모름으로 나왔고 오답은 적게 나왔다. 이 지시가 없는 RAG 생성 프롬프트에서는 같은 공백이 오답으로 나올 수 있다(추정). 결국 이 측정은 Hallucination 경향보다 "모델이 이 Corpus를 모르는 정도"를 더 직접 잰다.

## 문항의 한계

- 문항은 LLM(Claude Sonnet)이 원문에서 뽑고 근거 인용을 기계적으로 검증했다. 사람 검토는 아직 하지 않았다.
- `es_toolkit_ko-02`, `es_toolkit_ko-05`는 근거 인용이 참조 답의 일부만 덮는다. 나머지 근거는 같은 파일의 바로 다음 줄이나 표에 있다.
- 후보당 10문항이라 오답 비율의 신뢰구간이 넓다(10문항 중 5개 오답이면 95% 구간이 대략 0.24~0.76). 오답 비율은 큰 차이만 판정에 쓴다.

과제가 요구하는 Gold Set(사실, 다중 문서 종합, 요약, 답 없음, 함정)과 Part C 가설(고유 식별자가 많은 질의에서 Hybrid 검색 효과)을 기준으로 각 후보를 평가했다.

## 결정

**선정: `uv_docs`** (`astral-sh/uv` `docs/`, commit `5ce34500b8a3d16d24bc7576bd8ac64879091cea`, 문서 81개, 환산 181페이지).

선정 근거는 두 질문에 대한 답이다.

1. **이 Corpus에 RAG가 필요한가.** 근거 없이 물었을 때 모델의 지식 공백(오답 + 모름)이 uv_docs 4/10, es_toolkit_ko 4/10, k8s_ko_concepts 0/10, fastapi_ko 0/10이다. 앞의 두 후보만 모델이 모르는 내용을 담고 있다(8/20 대 0/20, Fisher 양측 p ≈ 0.003). uv_docs에서는 낡은 사전 지식이 현재 동작처럼 답해지는 Hallucination 사례(`uv_docs-10`, 3회 모두)도 관찰됐다.
2. **이 Corpus로 과제가 요구하는 Gold Set과 Part C 실험을 만들 수 있는가.** 남은 두 후보 중 uv_docs만 가능하다.
   - 문서 88%가 다른 문서를 참조해 다중 문서 종합 문항(Gold Set 25%)을 만들 수 있다. es_toolkit_ko는 61%가 독립 문서다.
   - 문서 길이 중앙값이 4,053자로 요약 문항(15%)이 성립한다. es_toolkit_ko는 1,228자다.
   - 버전 표기가 문서당 3.58로 가장 많아 함정 문항(10%) 재료가 충분하다. es_toolkit_ko는 0.02다.
   - CLI 옵션과 `UV_*` 환경변수 같은 정확한 식별자가 많아 Part C의 Hybrid 검색 가설을 검증하기 좋다.

다른 후보를 고르지 않은 이유:

- `k8s_ko_concepts`: 모델이 30회 모두 정답을 냈다. 근거 없이도 아는 내용이라 RAG의 효과와 Hallucination을 보이기 어렵다. 정제 비용도 4배 이상이다.
- `es_toolkit_ko`: 모델이 모르는 내용은 uv_docs만큼 있지만, 독립된 짧은 레퍼런스 페이지 위주라 Gold Set 구성(다중 문서 종합, 요약, 함정)을 채우기 어렵다.
- `fastapi_ko`: 대조군. 모델이 30회 모두 정답을 냈다.

감수하는 점:

- 영어 Corpus다. 과제는 언어를 제한하지 않지만 한국어 형태소 분석 실험은 하지 않게 되고, BM25 토크나이저 선택지가 단순해진다.
- closed-book 문항이 후보당 10개라 uv_docs와 es_toolkit_ko 사이의 지식 공백 차이는 판별하지 못한다. 두 후보 사이의 선택은 구조 지표로 했다.

## 사전 기준과의 차이

실험 전에는 "오답 문항이 대조군보다 3개 이상 많으면 확정, 어느 후보도 만족하지 않으면 문항을 20개로 늘려 재측정"으로 정했다. 결과는 어느 후보도 만족하지 않았다(uv_docs, es_toolkit_ko 모두 대조군보다 1개 많음).

재측정 대신 판정 지표를 지식 공백(오답 + 모름)으로 바꿔 확정했다. 이유는 다음과 같다.

- 질의 프롬프트에 "확실하지 않으면 모른다고 답하라"는 지시를 넣어, 모델이 모르는 내용 대부분이 오답이 아니라 모름으로 나왔다. 오답만 세는 기준은 이 도구 설계 때문에 구조적으로 낮게 나온다. 문항을 20개로 늘려도 이 문제는 그대로다.
- 데이터셋 선정에 필요한 판단은 "모델이 모르는 내용이 있어 RAG가 필요한가"이고, 이는 지식 공백이 더 직접 잰다.
- 재측정으로 바뀔 수 있는 판단은 uv_docs와 es_toolkit_ko 사이의 선택뿐인데, 이 선택은 closed-book이 아니라 구조 지표로 갈린다.
- Hallucination이 실제 RAG 프롬프트에서 얼마나 드러나는지는 Part B에서 Faithfulness와 답 없음 문항으로 다시 측정한다.

기록해 두는 교훈: closed-book 프롬프트에 모름 허용 지시를 넣으면 Hallucination 경향이 아니라 보정된 지식 범위를 재게 된다. 두 가지를 모두 재려면 모름 허용 지시가 있는 프롬프트와 없는 프롬프트를 나란히 써야 했다.

```
make corpus            # 원문 받기와 해시 검증
make profile           # 통계

```
