# Embedding 모델 선정

상태: 확정(**Qwen/Qwen3-Embedding-0.6B**). Chunking 확정 뒤 교차 확인(선정 실험 7단계)에서 2위 `intfloat/multilingual-e5-large`와 다시 비교해 확정했다. 결과는 "교차 확인" 절에 있다.

## 질문

이 Corpus에서 질문에 맞는 근거를 가장 잘 찾는 임베딩 모델은 무엇인가. 한국어 질의(영어 문서)도 감당하는가.

## 후보

엘리스 모델 라이브러리에 임베딩 모델이 없어 로컬 오픈소스 모델(fastembed, ONNX, CPU)만 비교했다. 성격이 겹치지 않게 골랐다.

| 후보 | 차원 | 최대 입력 | 언어 | 고른 이유 | 질의 접두어 / 문서 접두어(모델 카드 기준) |
|---|---|---|---|---|---|
| BAAI/bge-small-en-v1.5 | 384 | 512 | 영어 | 소형 기준선 | `Represent this sentence for searching relevant passages: ` / 없음 |
| BAAI/bge-base-en-v1.5 | 768 | 512 | 영어 | 같은 계열에서 크기 증가 효과 | 같음 |
| snowflake/snowflake-arctic-embed-m | 768 | 512 | 영어 | 검색 전용 학습 | 같음 |
| nomic-ai/nomic-embed-text-v1.5 | 768 | 8192 | 영어 | 긴 입력 | `search_query: ` / `search_document: ` |
| intfloat/multilingual-e5-large | 1024 | 512 | 다국어 | 한국어 질의 | `query: ` / `passage: ` |
| Qwen/Qwen3-Embedding-0.6B | 1024 | 32768 | 다국어 | LLM 기반 임베딩 | `Instruct: Given a question about the uv Python package manager, retrieve documentation passages that answer the question\nQuery: ` / 없음 |

접두어는 fastembed의 `query_embed`에 맡기지 않고 직접 붙여 모든 모델을 같은 규칙으로 다뤘다.

## 고정한 변인

| 변인 | 값 |
|---|---|
| Corpus, 정제 | `uv_docs` 81개 문서, Ingest 최소 구현 |
| 청크 | 고정 길이 1,000자, 겹침 없음. 587개. 모든 후보에서 최대 토큰 450~480으로 잘린 청크 0개 |
| 저장과 검색 | Qdrant(선정 DB), 정확 검색 모드(`exact=True`), dense top-10 |
| 질의 | dev set 답 있는 30문항. 영어 정본과 한국어 번역 묶음 각각 |
| 실행 | Docker(linux/aarch64) CPU, 후보를 하나씩 순서대로 |

## 지표

검색된 청크에 Gold 근거 구절이 들어 있는지로 판정한다(`app/service/eval/retrieval_metric.py`).

- 근거 판정: 근거 구절을 정제한 뒤 60자 창을 30자 간격으로 자르고, 같은 문서의 청크에 창 하나라도 그대로 있으면 그 근거를 찾은 것으로 본다. 고정 길이 분할이 구절을 청크 경계에서 끊어도 판정할 수 있게 하기 위해서다. 이 규칙으로 근거 62개 중 61개를 어떤 청크에서든 찾을 수 있다(나머지 1개는 72자 문장이 경계에서 반으로 갈린 경우). 이것이 이 청크 설정의 상한이다.
- 주 지표: Hit@5(상위 5개 안에 근거가 있는 문항 비율), MRR@10.
- 보조 지표: Hit@10, 근거 재현율@10(문항의 근거 여러 개 중 찾은 비율), 문서 단위 Recall@5.
- 신뢰구간: 문항을 복원 추출하는 bootstrap 2,000회(seed 2026) 95% 구간. 모델 비교는 같은 문항끼리 짝지은 차이의 구간으로 하고, 구간이 0을 포함하면 차이 없음으로 본다.

## 판정

1. **영어 질의만 보면 결정할 수 없다.** 여섯 모델이 통계적으로 같다. 이 경우 사전 규칙(차이 없으면 비용)으로는 bge-small이 된다.
2. **한국어 질의를 범위에 넣으면 다국어 모델만 남는다.** dev set에 한국어 번역 묶음을 둔 이유가 한국어 사용자 질의를 다루기 위해서였으므로, 한국어에서 Hit@5가 절반 아래로 떨어지는 영어 전용 모델은 탈락시킨다.
3. **Qwen3와 e5는 주 지표가 같다.** 사전 규칙의 다음 기준(비용, 지연)은 e5가 유리하다(색인 23% 빠름, 질의 35~48% 빠름).

**결정: Qwen3-Embedding-0.6B(잠정).** 사전 규칙과 다르게 비용 대신 아래 두 이유를 우선했다.

- 최대 입력이 32,768토큰이다. e5는 512토큰이라, 다음 Chunking 실험의 크기 후보 1024를 처음부터 뺄 수밖에 없다. 임베딩 선택이 다음 실험의 탐색 범위를 줄이지 않게 한다.
- 보조 지표(Hit@10, 근거 재현율)가 Qwen 쪽으로 기운다. 판정 경계라 결정적 근거는 아니다.
- 질의 지연 차이(50~100ms)는 LLM 생성 지연(초 단위)에 비해 작다.

e5는 2위로 두고 Chunking 확정 뒤 교차 확인에서 다시 비교한다. 그때도 주 지표가 같고 Chunking이 512토큰 이하로 정해지면 비용 규칙에 따라 e5로 바꾼다.

## 교차 확인(선정 실험 7단계)

결론: **Qwen3-Embedding-0.6B 확정.** Hit@5는 차이가 없고, e5는 근거 보존@5가 두 언어 모두 낮아 규칙 3번에 해당한다.

### 방법

Chunking 선정에서 확정한 `structure-512-77` 청크(길이는 Qwen3 토큰)를 두 모델에 그대로 넣는다. 청크를 모델마다 다시 자르지 않아 Chunking 변인을 고정한다. e5는 최대 입력이 512토큰이라 e5 토큰으로 512를 넘는 청크는 뒷부분이 임베딩에 반영되지 않는다. 이 잘림은 e5를 이 청크 설정으로 쓸 때 실제로 생기는 손실이라 그대로 두고, 잘린 청크 수를 함께 기록한다.

지표는 Chunking 선정과 같다(Hit@5, MRR@10, 근거 보존@5와 @10, 질의당 근거 토큰 수). 근거 토큰 수는 모델마다 자기 토크나이저로 센다.

### 판정 규칙(실험 전에 정함, `judge`로 구현)

계획서는 "순위가 뒤집혀도 차이가 구간 안이면 원래 선택 유지"였고, 위 판정은 "주 지표가 같고 Chunking이 512토큰 이하면 비용 규칙으로 e5"였다. 두 규칙은 동률일 때 결론이 다르다. Chunking 선정에서 얻은 교훈(생성 단계에 들어가는 상위 k개의 근거 보존을 비용보다 먼저 본다)을 반영해 다음 순서로 정한다.

1. 영어, 한국어 중 한 언어라도 Hit@5 짝지은 차이 구간이 0을 벗어나면 앞선 모델을 고른다.
2. 차이가 없으면 근거 보존@5를 본다. e5가 두 언어 모두 Qwen3 이상이면 비용(색인 23% 빠름, 질의 35~48% 빠름)으로 e5를 고른다.
3. 그렇지 않으면 Qwen3를 유지한다.

e5를 고르면 청크 길이 단위를 e5 토큰으로 바꿔 Chunking 2단계를 다시 실행한다.

### 결과

| 모델 | 언어 | Hit@5 [95% CI] | Hit@10 | MRR@10 | 근거 보존@5 | 근거 보존@10 | 근거 토큰 수 |
|---|---|---|---|---|---|---|---|
| **Qwen3** | 영어 | 0.933 [0.83, 1.00] | 0.933 | **0.812** | **0.867** | **0.867** | 1,843 |
| e5 | 영어 | 0.933 [0.83, 1.00] | **0.967** | 0.742 | 0.733 | 0.767 | 2,124 |
| **Qwen3** | 한국어 | **0.933** [0.83, 1.00] | 0.933 | 0.677 | **0.800** | **0.833** | 1,823 |
| e5 | 한국어 | 0.900 [0.77, 1.00] | 0.933 | **0.797** | 0.700 | 0.733 | 2,363 |

근거 토큰 수는 모델마다 자기 토크나이저로 센 상위 5개 청크의 합이다. 청크는 두 모델이 같다.

| 짝지은 차이(Qwen3 - e5) | 영어 | 한국어 |
|---|---|---|
| Hit@5 | 0.00 [0.00, 0.00] | +0.03 [0.00, 0.10] |
| MRR@10 | +0.07 [-0.03, 0.18] | -0.12 [-0.25, 0.01] |

| | Qwen3 | e5 |
|---|---|---|
| 모델 최대 입력을 넘는 청크 | 0 / 396 | **130 / 396 (32.8%)** |
| 청크 평균, 최대 토큰(모델 토크나이저) | 347, 512 | 415, 707 |
| 색인 시간 | 287초 | 224초 |

### 해석

- **Hit@5는 두 언어 모두 차이가 없다.** 규칙 1번에 해당하지 않는다.
- **e5는 청크의 3분의 1이 잘린다.** Qwen3 토큰 기준 512인 청크가 e5 토큰으로는 최대 707이다. 잘린 뒷부분은 벡터에 반영되지 않아, 근거가 청크 뒤쪽에 있는 문항은 검색 순위가 내려간다(추정). 근거 보존@5가 영어 0.13, 한국어 0.10 낮은 것과 방향이 맞다. 규칙 3번에 따라 Qwen3를 유지한다.
- **한국어 MRR은 e5가 0.12 높다.** 구간 상한이 0.006으로 판정 경계다. 첫 근거의 순위는 e5가 앞서지만, 상위 5개가 근거 전체를 덮는 비율은 Qwen3가 앞선다. 4단계(고정 1,000자 청크)에서도 한국어 MRR은 e5가 0.03 높았다.
- **Qwen3 결과는 Chunking 선정의 `structure-512-77`과 소수점까지 같다.** 같은 청크, 같은 모델로 다시 돌려도 같은 값이 나온다는 확인이다.

### 결정

**Qwen3-Embedding-0.6B를 확정한다.** 청크 길이 단위(Qwen3 토큰)와 Chunking 설정(`structure-512-77`)도 그대로 유지하고, 6단계는 다시 실행하지 않는다.

남은 질문: e5의 한국어 MRR 우위가 잘림 없는 청크(e5 토큰 기준 512)에서도 유지되는지는 재지 않았다. 확인하려면 e5 토큰으로 Chunking 2단계를 다시 돌려야 한다(약 30분). 한국어 질의 성능을 올리는 Part C 후보로는 질의 번역이 더 직접적이라 이쪽은 미룬다.

## 한계

- **dev set이 쉽다.** 가장 작은 모델도 영어 Hit@5가 0.90이라 위쪽이 막혀 있고, 30문항에서는 95% 구간 반폭이 약 0.13이다. 이보다 작은 모델 간 차이는 이 dev set으로 가릴 수 없다.
- CPU에서만 쟀다. GPU 환경에서는 Qwen3와 e5의 비용 차이가 줄어든다.
- fastembed가 제공하는 ONNX 변환본을 썼다. 원본(PyTorch) 모델과 점수가 미세하게 다를 수 있다.
- 한국어 묶음은 LLM 번역이다. 실제 사용자 질문의 표현은 다를 수 있다.
- Qwen3의 instruction 문구는 하나만 썼다. 문구에 따라 점수가 달라질 수 있다.

make embed-check   # 교차 확인: structure-512-77 청크로 Qwen3와 e5 측정(CPU에서 약 10분)
