# LLM 선정

상태: 확정(**claude-haiku-5-5**, 엘리스 ML API Serverless). 품질 하한을 넘은 후보가 Claude Haiku 5.5 하나였고, 비용도 가장 낮다.

## 질문

품질 하한을 넘는 생성 모델 중 비용이 가장 낮은 것은 무엇인가.

## 후보

| 모델 | 입력 단가 | 출력 단가 | temperature 0 | seed |
|---|---|---|---|---|
| claude-haiku-5-5 | ₩141 / 100만 토큰 | ₩708 / 100만 토큰 | 받음 | 거부(400) |
| gemini-3.8-flash | ₩1,063 / 100만 토큰 | ₩5,315 / 100만 토큰 | 받음 | 거부(400) |

단가는 엘리스 ML API 모델 라이브러리의 Serverless 요금(VAT 별도)이고 캐시 입력 할인은 반영하지 않았다. 두 모델 모두 `seed`를 넘기면 400으로 거부해, `LlmClient`가 seed를 생략할 수 있게 바꿨다. temperature는 0으로 고정하고 문항당 한 번 호출했다. gemini-3.8-flash는 답 전에 추론 토큰을 쓰고, 추론 토큰도 출력으로 과금된다.

데이터셋 선정과 dev set 구축에 쓴 `gpt-6.1-terra`는 temperature를 기본값(1) 외에는 받지 않아 같은 조건으로 비교할 수 없어 후보에서 뺐다.

## 고정한 변인

| 변인 | 값 |
|---|---|
| 검색 | Qwen3-Embedding-0.6B, `structure-512-77`, Qdrant 정확 검색 dense 상위 5개(6, 7단계) |
| 거절 1단계 | dense 최고 점수 0.6375 미만이면 LLM을 부르지 않음(8단계) |
| 프롬프트 | `prompt_builder`(8단계). 번호 매긴 근거, `[n]` 인용, `INSUFFICIENT_CONTEXT`, 문서 속 지시 무시 |
| 출력 상한 | 1,500토큰 |
| 질의 | dev set 76문항(영어, 한국어 각 38). 검색 단계에서 9문항이 거절돼 67문항을 LLM에 보낸다 |

## 지표

- **형식 준수율**: LLM이 답한 응답 중 형식을 지킨 비율. 거절이면 `INSUFFICIENT_CONTEXT`만 냈는지, 답이면 유효한 `[n]` 인용이 하나 이상 있는지 본다.
- **지운 인용 비율**: 근거에 없는 번호(예: 근거 5개인데 `[7]`)의 비율
- **답 있는 문항 오거절**: 답 있는 문항을 거절한 비율(검색 단계와 생성 단계 합)
- **답 없는 문항 거절**: 답 없는 문항을 거절한 비율(검색 단계와 생성 단계 합)
- **문항당 비용**: 검색 단계 거절(0원)을 포함한 문항당 평균 원화
- **지연**: LLM 호출의 평균과 p95(검색 단계 거절 제외)

## 판정 규칙(실험 전에 정함, `pick_llm`으로 구현)

1. 형식 준수율 95% 이상, 답 있는 문항 오거절 10% 이하를 **영어, 한국어 각각** 만족하는 후보만 남긴다(계획서의 품질 하한).
2. 그중 문항당 평균 비용이 가장 낮은 후보를 고른다.

## 결과

| 모델 | 언어 | 형식 준수 | 지운 인용 | 오거절(답 있음) | 거절(답 없음) | 문항당 비용 | 지연 평균 | 지연 p95 |
|---|---|---|---|---|---|---|---|---|
| **claude-haiku-5-5** | 영어 | 1.000 | 0.000 | **0.033** | 1.000 | **₩0.79** | **3.2초** | **5.5초** |
| **claude-haiku-5-5** | 한국어 | 1.000 | 0.000 | **0.000** | 1.000 | **₩0.94** | **3.7초** | **6.7초** |
| gemini-3.8-flash | 영어 | 1.000 | 0.000 | 0.100 | 1.000 | ₩4.53 | 5.8초 | 11.5초 |
| gemini-3.8-flash | 한국어 | 1.000 | 0.000 | 0.133 | 1.000 | ₩4.86 | 5.9초 | 10.9초 |

| 모델 | LLM 호출 | 호출당 입력 토큰 | 호출당 출력 토큰 | 실험 비용(VAT 별도) |
|---|---|---|---|---|
| claude-haiku-5-5 | 67 | 3,952 | 599 | 약 ₩66 |
| gemini-3.8-flash | 67 | 2,269 | 548(추론 포함) | 약 ₩357 |

같은 프롬프트인데 호출당 입력 토큰이 다른 것은 모델마다 토크나이저가 달라서다.

### 해석

- **두 모델 모두 형식을 지키고 근거에 없는 번호를 쓰지 않았다.** 검색 단계를 통과한 답 없는 문항 7개도 두 모델 모두 `INSUFFICIENT_CONTEXT`로 거절했다.
- **gemini-3.8-flash는 다중 문서 문항을 거절한다.** 오거절 7건 중 5건이 multi_doc이다. 상위 5개 근거에 답의 일부만 있으면 답 전체를 거절했다. claude-haiku-5-5는 같은 문항에서 근거가 있는 부분만 답하고 "문서에 없다"고 밝혔다(아래 검토). 한국어 오거절 0.133(4/30)이 하한 10%를 넘어 탈락했다. 두 언어를 합쳐 재도 0.117이라 판정은 같다.
- **claude-haiku-5-5의 오거절 1건**은 영어 trap 문항(AWS Lambda 계층에 `uv pip install`의 `--target` 대신 쓸 플래그, 정답 `--prefix`)이다. 한국어 번역 문항에는 답했다. gemini-3.8-flash도 이 문항을 거절했다.
- **비용은 claude-haiku-5-5가 약 5.4배 낮고 지연도 짧다.** 단가 차이(7.5배)를 입력 토큰 수 차이가 일부 상쇄했다.

### 근거 밖 내용 검토

계획서의 수동 검토 항목이다. claude-haiku-5-5의 영어 답 중 위험이 큰 7문항(trap 5개, gemini-3.8-flash가 거절한 multi_doc 2개)을 Claude(이 저장소의 작업 에이전트)가 근거, 정답과 대조해 읽었다. 사람 검토가 아니다.

- 7문항 모두 근거 밖 사실을 보태지 않았다. 명령, 플래그, 설정 키는 근거 그대로였다(`uv export --format cyclonedx1.5`, `--with-executables-from`, `match-runtime = true`).
- 근거에 없는 부분은 "문서에 없다"고 밝혔다. 예: Python 자동 다운로드 문항에서 설정 파일 경로(`~/.config/uv/uv.toml`)와 프로젝트 재정의 여부가 상위 5개 근거에 없어 그 부분을 답하지 않았다. 이는 검색 누락이고 10단계(검색 성능 평가)에서 다시 본다.
- 함정 문항에서 preview 상태(CycloneDX 내보내기)를 빠뜨리지 않았다.

전수 검토와 Judge 판정은 11단계(생성 성능 평가)에서 한다.

## 결정

**claude-haiku-5-5.** 품질 하한을 두 언어 모두 넘은 유일한 후보이고 비용과 지연도 가장 낮다. Query 경로는 `LLM_MODEL=claude-haiku-5-5`와 해당 엔드포인트(`LLM_BASE_URL`)로 띄운다.

Judge 모델은 생성 모델과 다른 계열이어야 하므로(Part B), Anthropic 계열은 Judge 후보에서 뺀다.

## 다음 단계에 주는 영향

- **Query 경로**: 문항당 비용은 약 ₩0.8~0.9, LLM 지연은 평균 3~4초, p95 5.5~6.7초다. API 타임아웃(60초)과 동시 호출 상한(4)은 이 값으로 충분하다.
- **Streaming 단계**: 첫 토큰 지연은 아래 "첫 토큰 지연(Streaming 구현 후 측정)" 절에 있다.
- **11단계**: 답이 평균 600토큰으로 길다. 루브릭의 "핵심 요점"과 별개로 장황함이 Answer Correctness 판정에 영향을 주는지 본다.

## 첫 토큰 지연(Streaming 구현 후 측정)

선정 때는 비스트리밍 호출만 해서 첫 토큰 지연을 재지 못했다. `/v1/query/stream`을 만든 뒤, 실행 중인 API 서버(`make serve`)에 dev set 답 있는 문항 앞 10개씩(영어, 한국어)을 순서대로 보내 서버가 기록한 `meta.first_token_ms`(검색 포함, 첫 `token` 이벤트까지)와 `meta.latency_ms`를 모았다. 측정 스크립트는 저장소에 두지 않은 일회성 실행이다.

| 언어 | 답한 문항 | 첫 토큰 중앙값 | 첫 토큰 최대 | 전체 중앙값 | 전체 최대 |
|---|---|---|---|---|---|
| 영어 | 10 / 10 | 2.30초 | 5.39초 | 2.84초 | 5.90초 |
| 한국어 | 9 / 10 | 2.31초 | 3.75초 | 2.86초 | 4.63초 |

- 첫 토큰까지가 전체 시간의 약 80%다. 게이트웨이가 텍스트를 큰 덩어리로 보내 첫 토큰 뒤 0.5초 안팎에 생성이 끝난다. 스트리밍으로 줄어드는 체감 대기는 0.5초 정도다.
- 한국어 1문항(사실형, "빌드 제약 조건 파일에 나열한 패키지가 설치되는가")은 이번에 근거 부족 토큰으로 거절됐다. 선정 실험에서는 같은 문항에 답했다. temperature 0이어도 호출마다 판단이 갈릴 수 있다는 관찰이고, 운영 검색이 HNSW 근사 검색이라 선정 실험(정확 검색)과 근거가 달랐을 가능성도 있다(미확인).

## 한계

- 후보가 둘이다. 엘리스 모델 라이브러리의 다른 생성 모델은 비교하지 않았다.
- temperature 0이어도 출력이 완전히 같다는 보장은 없다. 문항당 한 번만 호출했다. 응답을 캐시에 저장해 같은 입력이면 다시 부르지 않고 같은 답을 쓴다.
- 30문항이라 오거절 한 칸이 0.033이다. gemini-3.8-flash의 영어 오거절 0.100은 하한 경계다.
- 근거 밖 내용 검토는 7문항 표본이고 사람이 아닌 Claude가 했다.

## 재현

```
make llm-bench   # Qdrant 기동, 확정 구성으로 색인과 검색, 후보마다 생성, Qdrant 정지(첫 실행 약 10분, 엘리스 API 비용 발생)
```

응답은 `research/artifacts/llm_selection/responses.jsonl`에 요청 해시로 캐시된다. 같은 설정으로 다시 돌리면 API를 부르지 않고 같은 결과가 나온다(단가 반영을 위한 두 번째 실행에서 API 호출 0회, 캐시 파일 변경 없음을 확인했다).

- `answers.jsonl`: 후보, 문항별 답, 거절 단계, 인용, 토큰, 지연
- `results.json`: 후보와 언어별 요약
- `verdict.json`: 하한을 넘은 후보와 선택
