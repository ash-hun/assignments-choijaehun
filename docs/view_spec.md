# RAG QA 화면 기능 정의서

---

## 화면 목록

| 화면 | 경로 | 기능 | 구현 파일 | 상태 |
|---|---|---|---|---|
| 실시간 평가 대시보드(제목 Elice HR Assignments) | `GET /dashboard` | 실제 질의마다 쌓이는 지표의 누적 평균, 95% 구간, 최근 50건 이동 평균, Gold Set 기준선과 판정을 지표별 차트로, 최근 질의 100건을 10건씩 표로 보여준다 | `app/api/static/metrics_dashboard.html` | 구현됨 |

## 실시간 평가 대시보드

**목적**: 서비스가 실제 질의를 받는 동안 품질과 운영 지표가 어떻게 변하는지, Gold Set 기준선에서 얼마나 떨어져 있는지 본다.

**데이터 출처**: 화면이 `GET /v1/metrics/stream`(SSE)에 연결해 `snapshot` 이벤트를 받을 때마다 다시 그린다. 서버는 기록이나 판정이 늘 때마다 보낸다. 페이지 HTML 자체에는 데이터가 없다.

### 구성

| 영역 | 내용 |
|---|---|
| 머리말 | 제목 "Elice HR Assignments", 화면 설명 한 줄 |
| 요약 줄 | 질의 수, 답한 수, Judge 판정 수, Judge 비용 / 상한을 한 줄로. 같은 줄 끝에 연결 문구(끊김이나 실패일 때만)와 마지막 갱신 시각(snapshot을 받은 브라우저 시각, HH:MM:SS). 버튼과 API 키 입력은 없다 |
| 식별 정보 | 설명 아래 작은 글씨 한 줄: 구성(`config_id`), 기준선 실행(run_id 또는 없음) |
| 범례 | 누적 평균(선), 95% 구간(띠), 최근 50건(선), Gold Set 기준선(점선) |
| 배치 | 폭 1100px 넘으면 두 열. 왼쪽에 지표 탭, 오른쪽에 최근 질의 표. 1100px 이하면 한 열로 지표 탭, 최근 질의 순. 본문 최대 폭 1760px |
| 창 높이 채우기 | 두 열이고 지표 영역에 쓸 높이가 420px 이상이면 창 아래 끝까지 채운다. 카드는 남은 높이만큼 커지고, 차트는 폭의 0.62배(220~380px)로 두고 남는 높이를 위아래 여백으로 나눠 세로 가운데에 놓는다. 표는 10줄 그대로 행 간격이 넓어진다. 페이지 스크롤은 생기지 않는다. 조건이 안 되면 차트 높이 220px 고정에 페이지 스크롤 |
| 지표 탭 | 검색, 생성, 운영 탭 중 하나를 골라 그 묶음의 카드만 보인다. 서버가 지표마다 준 `group`으로 나눈다. 검색(검색 단계 거절률, 임계값 근처), 생성(생성 단계 거절률, 근거 없는 주장 없음(참고값), Citation Precision(참고값)), 운영(Latency, TTFT, 질의당 비용). 탭 아래 한 줄 설명. 카드는 탭 안에서 한 줄로 놓고, 700px 이하에서만 한 열로 쌓는다. 같은 줄 카드의 머리말 높이를 가장 긴 것에 맞춰 차트 위치를 맞춘다 |
| 지표 카드 | 지표마다 하나. 제목, 참고값 표시(해당 시), 기준선 판정 배지, 현재 값 한 줄(누적 [구간], 최근, 기준선, 기준선 대비 차이), 차트(x축 표본 수 눈금 처음, 가운데, 끝, y축 값) |
| 기준선 판정 배지 | 기준선 수준(초록, 기준선이 누적 95% 구간 안), 기준선보다 높음, 기준선보다 낮음(주황, 구간 밖), 표본 10건 미만(점선 테두리). 좋고 나쁨이 아니라 차이 여부만 표시한다 |
| 차트 값 보기 | 마우스를 올리거나 차트에 포커스한 뒤 좌우 화살표 키로 지점을 고르면 n, 누적, 구간, 최근 50건 값이 말풍선으로 뜬다. Esc나 포커스 이탈로 닫는다 |
| 최근 질의 표 | 서버가 보낸 최신 100건을 페이지당 10건으로 나눈다. 이전, 다음 버튼과 "현재 / 전체 (총 N건)". 시각(HH:MM:SS, 마우스를 올리면 MM-DD 포함, 브라우저 시간대), 요청 ID(잘리면 마우스를 올려 전체), 상태(답함, 거절(검색), 거절(생성)), 최고 점수, Latency, TTFT, 비용, Judge(근거 통과/실패와 CP, 대기, 판정 오류, -). 칸이 넘치면 표만 가로로 스크롤 |

지표 카드 순서: 검색 단계 거절률, 검색 최고 점수가 임계값 ±0.05 안, 생성 단계 거절률(검색 통과 질의), 근거 없는 주장 없음(참고값), Citation Precision(참고값), Latency(답한 질의), TTFT(답한 질의), 질의당 비용.

### 상태

| 상태 | 보이는 것 |
|---|---|
| 처음 열었을 때 | 바로 연결을 시도한다. 연결 전 지표 영역에는 "연결하면 지표가 표시된다." |
| 기록 0개 | 요약 줄은 0, 지표 카드마다 "아직 값이 없다", 최근 질의 표 "아직 질의가 없다", 페이지 "1 / 1 (총 0건)"에 이전, 다음 비활성 |
| 새 snapshot 수신 | 보고 있던 페이지 번호를 유지한다. 새 질의가 앞에 붙으므로 같은 페이지의 행은 한 칸씩 밀린다. 페이지 수가 줄면 마지막 페이지로 옮긴다 |
| 표본 1개 | 차트에 구간 띠 없이 점 하나 |
| 판정 0개 | Judge 지표 카드만 "아직 값이 없다". 나머지는 그려진다 |
| 기준선 없음 | 식별 정보 "기준선 실행 없음", 카드의 기준선 "-", 점선 없음 |
| Judge 예산 소진 | 요약 줄 끝에 빨간 글씨로 경고 "Judge 예산 소진: 채점을 멈췄다. 기록은 계속 쌓인다." |
| 401(서버에 `API_KEY` 설정됨) | 상태 문구 "연결 실패(401): 서버에 API_KEY가 설정돼 있어 대시보드에서 볼 수 없다". 화면에 키 입력이 없어 자동 재연결하지 않는다 |
| 503(실시간 평가 꺼짐) | 상태 문구 "연결 실패(503), N초 뒤 다시 연결". 자동 재연결 |
| 서버 종료, 네트워크 끊김 | 상태 문구 "연결 끊김, N초 뒤 다시 연결". 1초에서 두 배씩 늘려 최대 30초 간격으로 다시 연결하고, 연결되면 간격을 1초로 되돌린다 |

### 동작

- 차트는 카드의 실제 폭에 맞춰 그리고, 창 크기가 바뀌면 마지막 snapshot으로 다시 그린다.
- 탭은 클릭이나 좌우 화살표 키로 바꾼다. 처음 열면 검색 탭이고, 고른 탭은 이 브라우저의 `localStorage`에 남아 다음에 열 때 그 탭으로 연다(저장소를 못 쓰면 검색 탭). 새 snapshot이 와도 고른 탭은 유지한다.
- `EventSource`는 헤더를 실을 수 없어 `fetch` 스트림으로 SSE를 읽는다.
- 화면 폭이 좁으면 카드가 한 줄에 하나로 내려간다. 밝은 화면과 어두운 화면 설정을 따른다.

### 보안

- 모든 값은 `textContent`와 SVG 속성으로만 넣는다. `innerHTML`을 쓰지 않는다. 질문 원문과 답 원문은 화면에 없다. 요청 ID는 클라이언트가 보낸 `X-Request-ID`일 수 있어(형식은 미들웨어가 검사) 텍스트로만 넣는다.
- 외부 스크립트, 폰트, CDN을 쓰지 않는다. 차트는 SVG를 직접 그린다.
- 페이지는 인증 없이 열리고 `/v1/metrics/stream`을 키 없이 부른다. 서버에 `API_KEY`가 설정되면 데이터는 401로 막힌다. API 서버 포트는 `127.0.0.1`에만 열려 있다(`compose.yaml`).
