# 4. 임베딩 모델 선정

**결론(잠정): Qwen/Qwen3-Embedding-0.6B.** 2위 intfloat/multilingual-e5-large와 Chunking 확정 뒤 7단계에서 다시 비교한다.

## 질문

이 Corpus에서 질문에 맞는 근거를 가장 잘 찾는 임베딩 모델은 무엇인가. 한국어 질의(영어 문서)도 감당하는가.

## 후보

엘리스 모델 라이브러리에 임베딩 모델이 없어 로컬 오픈소스 모델(fastembed, ONNX, CPU)만 비교했다. 성격이 겹치지 않게 6종을 골랐다.

| 후보 | 차원 | 최대 입력(토큰) | 언어 | 고른 이유 |
|---|---|---|---|---|
| bge-small-en-v1.5 | 384 | 512 | 영어 | 소형 기준선 |
| bge-base-en-v1.5 | 768 | 512 | 영어 | 같은 계열에서 크기를 키운 효과 |
| snowflake-arctic-embed-m | 768 | 512 | 영어 | 검색 전용 학습 |
| nomic-embed-text-v1.5 | 768 | 8,192 | 영어 | 긴 입력 |
| multilingual-e5-large | 1024 | 512 | 다국어 | 한국어 질의 |
| Qwen3-Embedding-0.6B | 1024 | 32,768 | 다국어 | LLM 기반 임베딩 |

질의, 문서 접두어는 모델 카드에 적힌 대로 붙였다.

## 고정한 변인

- 청크: 고정 길이 1,000자, 587개. 모든 모델에서 잘린 청크 0개
- 저장과 검색: Qdrant 정확 검색 모드, dense top-10
- 질의: dev set 답 있는 30문항(영어, 한국어 각각)

## 결과

| 모델 | 영어 Hit@5 | 영어 MRR | 한국어 Hit@5 | 한국어 MRR | 색인 시간(587청크) |
|---|---|---|---|---|---|
| bge-base-en-v1.5 | **0.933** | 0.717 | 0.433 | 0.321 | 48.6초 |
| bge-small-en-v1.5 | 0.900 | 0.694 | 0.367 | 0.312 | 16.8초 |
| snowflake-arctic-embed-m | 0.833 | **0.759** | 0.433 | 0.286 | 77.5초 |
| nomic-embed-text-v1.5 | 0.833 | 0.717 | 0.367 | 0.263 | 89.7초 |
| Qwen3-Embedding-0.6B | 0.833 | 0.711 | **0.767** | 0.581 | 259.4초 |
| multilingual-e5-large | 0.800 | 0.678 | 0.733 | **0.610** | 200.6초 |

- **영어 질의로는 가를 수 없다.** 1위 대비 짝지은 차이의 구간이 모든 모델에서 0을 포함한다.
- **한국어 질의에서 다국어 모델만 남는다.** 영어 전용 모델은 한국어 질의에서 Hit@5가 0.40~0.53 떨어지고, 다국어 모델과의 차이 구간이 모두 0을 넘는다.
- **Qwen3와 e5는 주 지표가 같다.** Hit@5와 MRR의 짝지은 차이 구간이 두 언어 모두 0을 포함한다. 보조 지표(Hit@10, 근거 재현율)는 Qwen3 쪽으로 기울지만 구간 하한이 0.0이라 판정 경계다.
- 관찰: 영어 전용 모델도 한국어 함정 문항은 0.4~0.8을 맞혔다. 번역하지 않은 플래그, 환경변수가 질의에 남아 있어서다. 정확한 식별자 일치가 검색을 살린다는 뜻이라 Part C의 Hybrid 가설을 뒷받침한다.

## 결정과 이유

1. 한국어 질의를 범위에 넣으므로 영어 전용 모델 4종을 뺐다.
2. Qwen3와 e5는 주 지표가 같다. 사전 규칙의 다음 기준(비용)은 e5가 유리하다(색인 23% 빠름, 질의 35~48% 빠름).
3. **비용 대신 Qwen3를 골랐다.** 최대 입력이 e5는 512토큰, Qwen3는 32,768토큰이다. e5를 고르면 6단계 Chunking의 크기 후보 1024를 처음부터 뺄 수밖에 없다. 임베딩 선택이 다음 실험의 탐색 범위를 줄이지 않게 했다.

## 계획과 달라진 점

사전 규칙(주 지표가 같으면 비용이 낮은 쪽)대로라면 e5다. 위 3번 이유로 따르지 않았고, 그래서 결정을 잠정으로 두었다. 7단계에서 확정 Chunking으로 다시 비교했을 때도 주 지표가 같고 Chunking 크기가 512토큰 이하로 정해지면 비용 규칙에 따라 e5로 바꾼다.

## 한계

- dev set이 쉽다. 가장 작은 모델도 영어 Hit@5가 0.90이라 위쪽이 막혀 있다.
- CPU에서만 쟀다. GPU에서는 Qwen3와 e5의 비용 차이가 줄어든다.
- 한국어 묶음은 LLM 번역이라 실제 사용자 질문의 표현과 다를 수 있다.
- Qwen3의 instruction 문구는 하나만 썼다.
