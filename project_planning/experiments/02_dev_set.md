# 2. 선정용 질의셋(dev set) 작성

**결과: 영어 38문항(`data/gold/dev_set.jsonl`)과 한국어 번역 38문항(`data/gold/dev_set_ko.jsonl`), 근거 구절 62개**

## 목적

이후 모든 선정 실험(데이터베이스, 임베딩, 토크나이저, Chunking, 거절 임계값, LLM)에서 후보를 비교하는 질의셋이다. 최종 평가용 test set과 분리해 둔다.

## 구성

| 유형 | 문항 | 근거 구절 | 원문을 고른 규칙 |
|---|---|---|---|
| factual | 12 | 문항당 1개 | 최상위 섹션을 번갈아 뽑음 |
| multi_doc | 8 | 문항당 2~3개 | 실제로 서로 링크된 문서 쌍 |
| summary | 5 | 문항당 4~5개 | 6,000자 이상 문서 |
| trap | 5 | 문항당 1~2개 | preview, experimental, deprecated, 버전 번호가 많은 문서 |
| unanswerable | 8 | 없음 | 문서 목차만 주고 생성. 가까운 주제 4, 먼 주제 4 |

근거가 걸린 문서는 38개다(Corpus 81개 중).

## 만든 방법

1. **초안 생성**: LLM(`gpt-6.1-terra`)이 원문을 읽고 질문, 정답, 근거 구절을 JSON으로 낸다. 근거 구절은 원문과 글자 단위로 대조해(공백 차이만 허용) 맞지 않으면 1회 재시도하고, 그래도 틀리면 버린다. 38문항 모두 통과했다.
2. **사람 검수**: 38문항을 모두 읽고 4문항을 교체, 1문항을 수정했다.
   - 모델이 문서 없이도 아는 질문(uv의 구현 언어)은 검색 비교에 변별력이 없어 교체했다.
   - 일반 지식으로 맞힐 수 있는 함정 문항을 preview 기능 질문으로 교체했다.
   - 문서와 너무 먼 답 없는 문항 2개를 가까운 주제로 바꿨다. 예를 들어 "HTTP 요청 시간 제한"은 문서에 캐시 잠금 대기 시간(`UV_LOCK_TIMEOUT`)만 있어 검색이 엉뚱한 구절을 가져오게 유도한다.
   - 답 없는 문항은 핵심어를 원문에서 검색해 실제로 답이 없는지 확인했다.
3. **한국어 번역 묶음**: 질문만 번역하고, 명령, 플래그, 환경변수, 파일 경로는 그대로 두었다. 정답과 근거는 영어 원문 행과 같다.
4. **검증**: 스키마, id 중복, 근거 구절의 원문 일치, 번역 행과 원문 행의 짝을 자동 검사한다. 두 언어 모두 문제 0건.

문항 id는 `split`, 유형, 순번에서 계산하는 UUID라 초안을 다시 만들어도 바뀌지 않는다.

## 한계

- 초안과 교체 문항을 LLM이 썼고 검수자는 한 명이다. 질문 문체가 단조로울 수 있다.
- factual 12문항이 모두 근거 1개다. LLM 초안은 한 구절로 답이 되는 질문으로 쏠린다.
- 초안을 만든 모델이 9단계 LLM 후보이기도 하다.
- 답 있는 문항이 30개라 95% 신뢰구간 반폭이 약 0.13이다. 이보다 작은 차이는 이 셋으로 가릴 수 없고, 이 한계는 이후 모든 단계에 영향을 준다.

## 상세와 재현

- 상세 기록: [research/dev_set_construction.md](../../research/dev_set_construction.md)
- 재현: `make gold-draft SPLIT=dev`, `make gold-translate SPLIT=dev`, `make gold-check SPLIT=dev LANG_CODE=en|ko`
- LLM 출력은 매번 달라질 수 있어, 재실행은 `data/gold/drafts/`만 덮어쓰고 검수를 마친 정본은 그대로 둔다.
