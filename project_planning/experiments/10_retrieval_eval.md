# 10. 검색 성능 평가

**결론: 확정한 검색 구성(Qwen3-Embedding-0.6B, `structure-512-77`, dense 상위 5개)의 test set Recall@5는 영어 0.773, 한국어 0.703이다.** 근거를 가장 많이 놓치는 유형은 multi_doc(두 문서의 근거 중 하나만 찾음)이고, 한국어 trap 문항은 Recall@5가 0.500이다. 이 값이 Part C의 기준선이다.

## 질문

1~9단계에서 dev set으로 고른 검색 구성이, 선정에 쓰지 않은 test set에서 필요한 근거를 빠짐없이, 잡음 적게, 위쪽 순위로 가져오는가.

## 고정한 변인

| 변인 | 값 |
|---|---|
| 검색 | Qwen3-Embedding-0.6B, `structure-512-77`, Qdrant dense(HNSW), 컬렉션 `chunks_uv_docs_66b32940` |
| 생성에 넣는 근거 수 | 5(서비스 기본값) |
| 검색 지표 깊이 | 10 |
| 질의 | test set 영어 40문항, 한국어 번역 40문항. 검색 지표는 답 있는 32문항씩 |
| 경로 | API와 같은 조립(`query_builder`), 스트리밍 경로 |

생성, 거절, 운영 수치도 같은 실행에서 함께 기록했다. 생성 품질(Judge 지표)은 11단계에서 잰다.

## 지표

정의는 [research/gold_metric_selection.md](../../research/gold_metric_selection.md)의 "검색" 절과 같다. 관련 청크는 근거 구절의 60자 창이 들어 있는 같은 문서의 청크다. Recall@k는 근거 구절 단위, Precision@k는 청크 단위로 센다. 구간은 문항 bootstrap 95%(2,000회, seed 2026)다.

## 해석

- **multi_doc이 가장 약하다.** Recall@10이 1 미만인 15건 중 12건이 multi_doc이다. 대부분 두 문서 중 한쪽 근거만 찾았다(Recall 0.5). 질문에 두 주제가 섞이면 dense 질의 벡터가 한쪽 문서로 기운다.
- **한국어는 순위에서 손해를 본다.** Recall@10의 차이(0.888과 0.828)보다 MRR, nDCG의 차이가 크고, 검색 최고 점수가 임계값 근처에 몰린 질의가 2.6배 많다. 한국어 오거절 3건 중 1건(Coiled 기본 자원)은 최고 점수 0.6321로 임계값 바로 아래라 검색 단계에서 거절됐다.
- **trap은 영어에서도 nDCG가 낮다(0.572).** 근거는 10위 안에 들어오지만 위쪽에 오지 않는다. 버전, 식별자 같은 정확한 문자열이 답을 가르는 문항이라, BM25를 섞는 Hybrid 가설이 겨냥하는 영역이다.
- **Precision@k는 절대값으로 읽지 않는다.** factual 문항은 근거 구절이 하나라 Precision@5의 상한이 0.2 근처다. Part C에서 구성 간 비교에만 쓴다.
- 직접 쓴 교체 문항 `test-factual-01`(Python 사전 릴리스 선택)은 두 언어 모두 생성 단계에서 거절됐다. 영어는 근거 청크가 8위라 생성에 넣는 상위 5개 밖이었고, 한국어는 10위 안에서도 찾지 못했다. 근거를 상위 5개 밖에서 찾는 문항은 재순위화나 Hybrid로 올릴 수 있는 사례다.

## 기록하지 못한 문항

한국어 1문항(`test-factual-08`의 번역, "uv가 설치한 Python 버전을 저장하는 디렉터리를 출력하는 uv 명령어는 무엇인가요?")은 엘리스 게이트웨이 앞단의 Cloudflare WAF가 403으로 매번 막았다. 같은 문항의 영어판과 다른 78문항은 통과했다. 실제 사용자가 API로 같은 질문을 해도 502가 난다. 이 문항은 한국어 지표에서 빠졌고(39문항), Report에 id를 남겼다. 어떤 내용이 차단을 일으키는지는 확인하지 못했다.

## 한계

- 32문항이라 언어별 구간 폭이 0.2 안팎이다. 영어와 한국어의 차이는 구간이 겹쳐 차이가 있다고 판정할 수 없다.
- 관련 청크 판정이 근거 구절 문자열 일치라, 같은 내용을 다른 문장으로 담은 청크는 관련 청크로 세지 않는다.
- TPOT 중앙값이 1~2ms로, 답변 모델의 생성 속도보다 빠르다. 게이트웨이가 스트림을 묶어서 보내는 것으로 추정한다. 이 TPOT는 생성 속도가 아니라 게이트웨이 전달 속도에 가깝다.
